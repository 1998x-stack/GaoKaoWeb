# V1.3 教学资源体系 — Product / Data / Engineering Architecture
> Design baseline 2026-11-02. V1.3 is NOT implemented by this document. First deliver a compliant vertical slice; defer scalable authoring, accounts and AI until rights/evidence gates pass.

## 0. North Star

Turn the existing *historical exam syllabus index* into a **verifiable teaching resource system** rather than a scraped question warehouse.

- Student: choose province, exam year/plan, subject -> verified topic -> curated practice -> hints/explanations -> progress/path.
- Teacher: choose grade/course/period -> objectives -> legally reusable references + authored exercises -> teaching plan -> class/individual differentiation -> printable/exportable lesson pack.
- Editor: source/rights verification -> paper/question extraction -> tag verification -> solution review -> publication -> correction or takedown.
- Researcher: click each claim for issuer, release time, scope, rights and source evidence.

## 1. Key architectural decision — two axes rather than one 'verified' flag

A resource has two orthogonal gates:

(1) Authenticity: is this really the specified official statement, issued by this source, version, date, province and paper?
(2) Rights: may our site display, store, reproduce, adapt, export, embed, send to third-party AI, or redistribute it?

A third gate is pedagogical: is the solution/classification correct and suitable?

"Official" does not grant repost rights. "Open/free" does not grant modification rights. A paper review does not become a real exam paper.

1. source + rights + updatedAt block

## 3. Data domains (schemas and relations)

- SourceRecord: source_id, issuer, officialURL, announced_at, retrieved_at, content_hash, scope, URL status, archived evidence (if storage lawful).
- RightsGrant: grant_id, owner, evidence_url/document, license_code, granted_actions, valid_from/to, territorial constraints, third_party_terms, reviewer, decision_at.
- ExamPaper: paper_id, year, month, province, scheme, subject, paper_variant, source_id, status, exactness, official_question_set_id nullable.
- Question: qid, content_version, paper_id|null, original_author, source_id, rights_grant_id, stem, answer, reasoning, media, verification, question_type, difficulty, cognitive_dimensions, primary_topic_ids.
- TopicMapping: from_qid, to V1.2 topic_id, relationship=direct|supplementary|teacher_reviewed, model_score if suggested, adjudication.
- TeachingPack: pack_id, learning_objectives, prerequisites, audience, 45/90min outline, examples, exercise references, teacher notes, formative checks, resource rights.
- Pathway: path_id, target_audience, course_standard_version, province/scheme, ordered units, checkpoint conditions, rollback/review scheduling; route must not assume student has mastered a topic based on a "read" marker.
- Evidence: evidence_id, resource_id, canonical URL, locator=(section/page/paragraph/question_no), quoted_character_range if licensed, verified_by, verified_at, source_version; never fabricate page anchors.
- AuditEvent: event_id, resource_id, from_status, to_status, actor, reason, timestamp, source_hash; append-only.
- AIAnswer (future): source versions, retrieved spans, per-claim supporting citations, model run/version, guardrail result, uncertainty, evaluator version.

## 4. Classification taxonomy (orthogonal dimensions)

### Learning classification
- subject -> course standard version -> strand -> domain -> topic -> subskill
- cognitive competency: 识记/理解/迁移/综合探究; subject-specific core literacy separate and versioned
- solution strategy: 函数性质、分类讨论、构造、数形结合、换元、参数化、反证等

### Question classification
- formal type: single-choice, multi-choice, fill-in, short-answer, derivation/proof, experiment, reading, writing
- skill: calculation / reasoning / modeling / representation / experiment design
- difficulty: unassigned / teacher estimation / empirically measured (maintain source and method)
- common error: concept, condition omission, computation, domain, sign, proof gap, interpreting text
- provenance: original / verified licensed / official paper external link / simulated / unknown
- relation: only "exact_official_question" when officially confirmed; "inspired_by" or "simulated" must not masquerade as exact test.

### Regional exam applicability
Store exam_year and scheme together with region; a paper from 2019 cannot be presented as applicable in 2026 without evidence. Unknowns are null plus verification_status, not defaults or inferred labels.

## 5. Content lifecycle and publishing guard

External link: DISCOVERED -> URL_CHECKED -> METADATA_REVIEW -> LINK_ONLY_PUBLISHED -> WITHDRAWN
Hosted content: DISCOVERED -> RIGHTS_REVIEW -> TRANSCRIPTION -> ANSWER_REVIEW -> PEDAGOGY_REVIEW -> APPROVED -> PUBLISHED -> CORRECTED/RETIRED

**Block on missing rights**: hosted stem/answer/media requires explicit display grant or confirmed author ownership; download/export additionally requires distribution grant; translation/variation/AI ingest require distinct permissions. A license declaration does not automatically clear third-party embedded charts/photographs.

For hosted content every published question must have either [source_id,rights_grant_id] or an author-owned origin manifest with clear permissions, answer review and evidence chain.
For external-only: title+metadata+official link can be published after source and characterization review; no reproduction beyond appropriately authored metadata; never proxy external PDF.

One editor cannot approve their own high-risk disputed paper; dual review recommended for real official papers and math proof quality. Takedown is reversible in audit but immediate in public index and AI index.

### Phase-first implementation pattern

0–5000 reviewed resources: JSON/MDX + JSON Schema validation + generated static pages; Git PR is editorial system. No backend or credential storage required.
Beyond that: add a dedicated content management service, Postgres (resources, rights, audit events), object storage with explicit license scope, search index, and private teacher workspace with authorization. Do not place unrestricted teacher uploads in public repository.
No scraping farm or paywall bypass; adapters only for publicly permissible metadata retrieval and partner APIs.

### Performance and accessibility

- Static path pages, server-rendered descriptions, accessible math (MathML + LaTeX fallback) and keyboard-only practice.
- At first display no unnecessary account/session data; retain local progress in v2 store with migration support and version isolation.
- Low bandwidth mode avoids heavy PDF embeds, links direct to official sites.
- 100% pages contain year/province/rights state when resource suggests exam authenticity; no invented coverage.
- Printed packs include rights/attribution footers for each excerpt. If not distributable, show citation link rather than exporting the content.

## 7. Five rollout gates (sequence is intentional)

| Phase | Main output | Gate |
|---|---|---|
| V1.3.0 Source + rights foundation | schemas, source/rights registry, public link cards, editorial checks | ZERO unauthorized full texts; 100% publicly shown entries have resolvable author/origin and date/scope confidence |
| V1.3.1 Mathematics taxonomy + original items | 3 pilot topics: derivatives, conics, trigonometry; authored exercise versions | ≥95% teacher-reviewed labels, 100% reviewed answers, 100% rights decisions |
| V1.3.2 Teacher prep studio | 45/90-min objectives, lesson-plan templates, legally exportable packs, individual variant assignments | PDF/print/Markdown round-trip, permissions respected, teacher can correct labels |
| V1.3.3 Learning pathways | baseline diagnostic, practice set, checkpoint, review spacing; local progress | 100% tasks link to valid approved topics, prerequisite cycle detection, no false mastery claims |
| V1.3.4 Evidence-backed AI pilot | approved-only RAG with source/rights filter and claim-level citations, abstention | offline QA gold set (≥200 questions), no citation fabrication, 100% answers grounded or abstained |

These are **proposed acceptance gates** (not existing empirical results). Start with narrow Shanghai mathematics as a pilot *only after* the exam sources and their license implications are verified.

## 8. Quality metrics and independent evaluation

- Rights: zero published full-stem resources with unknown hosted rights; zero revoked item in exported/AI indexes.
- Provenance: every official label anchored to a verified issuer/version/source URL; every external link checked.
- Pedagogy: answer correctness 100% of approved items reviewed; math symbolic + numerical spot checks, two independent graders for high stakes.
- Retrieval: build ≥100 queries as a gold test, NDCG@10 and Recall@10 compared with V1.2 BM25; keep a hold-out set.
- Pathways: all prerequisite edges must be teacher-validated, graph DAG check, no circular references, diagnostic checkpoint tests.
- Frontend: mobile responsive, WCAG AA-oriented audits, keyboard navigation, SSR crawl/SEO, build-time broken-link validation.
- Performance: target p95 resource listing <1s for cached pages, client search <250ms on 1k items at representative hardware; performance assertions measured in CI, not claimed in advance.
- Audit: every status transition signed/logged; withdrawn items fail publication gate; rollback artifact hash recorded.
- Testing: isolated test runner (unit/schema/lint/e2e/build) distinct from independent evaluator (content correctness, rights inspection, retrieval ranking, AI groundedness).

## 9. Out of scope for initial V1.3

- No automated scraping of commercial question banks or bulk unauthorized PDF mirroring.
- No claim that Shanghai or national 2019 old outline is current 2026 regional curriculum.
- No public AI endpoint, scoring of individual minors, or upload of student data to LLMs until policy/consent/tech infrastructure passed.
- No live account-based teacher editing on static GitHub Pages without proper identity/access control.
- No copyrighted teacher slides/test banks preloaded just because accessible.
